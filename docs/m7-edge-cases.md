## Completion timing

`Completed at` is filled only when the entire row has revision-specific
evidence matching its required scope and its status is marked verified. Use
ISO 8601 timestamps with seconds and an explicit offset in Australia/Brisbane
(`+10:00`), recorded in the same update as status and evidence. Unverified rows
use `—`; a component pass or a planned test does not supply a completion time.
For historical evidence with no exact time, preserve the known date with
`(time not recorded)`, or use `unknown (historical)` when the date is unavailable.

Append first completions, reopenings, re-verifications, and newly discovered
cases to [Completion history](#completion-history), using stable row IDs and
links to the corresponding milestone task and evidence. Preserve the previous
completion in history before clearing `Completed at` on a reopened row. Record
corrections as new events. Count first completions separately from
re-verifications for cases completed per hour/day, and account for reopenings
and added scope. The timing baseline is an observation, not a completion event;
unknown historical times cannot support hourly rates. See the shared
[task timing rules](tasks.md#completion-timing).

## Agent Tunnel interpretations required for every row

Agent Tunnel has no deployed-content fallback after a request has selected an
owner, and an ambiguous owner/authorization/peer result fails closed. A known
unconfigured target may return a typed no-target result, but an unavailable
selected target must never be redirected to an unrelated adapter or backend.
This is the Agent Tunnel analogue of the source page's production-fallback
gate.

The source's SQLite rows are treated as the required pattern for any future
privileged adapter RPC. No SQLite dependency or SQLite implementation is added
by this document. Such an adapter must use the existing authenticated peer
transport, complete owner token, tenant/device/service scope, assignment and
epoch, bounded body, and explicit known/unknown outcome. A direct URL/token
fallback is forbidden.

Agent Tunnel scheduled M2 data-carrier rotation retains the owner, control
socket, logical streams, sequence fences, and adapter session while replacing
the data carrier within the bounded socket overlap. The Kaizen browser
1012-and-reconnect behavior is not copied into the Agent Tunnel rotation
contract. An owner change or process loss is a fresh-session interruption and
must be tested separately.
